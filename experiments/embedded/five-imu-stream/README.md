# Five IMU six-axis stream

Adafruit Feather ESP32-S3 PID 5477, STEMMA QT SDA GPIO3 / SCL GPIO4, power GPIO7, heartbeat GPIO13. PCA9548A at 0x70; ISM330DHCX at 0x6B on channels 3–7. Firmware enables accelerometer and gyro at nominal 104 Hz, +/-2 g and +/-250 degrees/s; it uses nominal sensitivities 0.000061 g/LSB and 0.00875 degrees/s/LSB. Values are scaled raw measurements, without bias calibration or fusion. BDU and register auto-increment are enabled. One burst reads status and all six axes per sensor. Status bits 0 and 1 indicate accelerometer and gyro data ready at the beginning of the burst; they do not count overwritten samples or guarantee simultaneous samples.

Each USB serial CSV row is sample,sweep,us,channel,status,ax_g,ay_g,az_g,gx_dps,gy_dps,gz_dps. The microsecond timestamp is captured after the sensor read, using the ESP timer since boot. Errors are error,sweep,us,channel,error_name. The target sweep period is 10 ms; delays and USB throughput can cause overruns. The bus runs at 400 kHz.

Build and upload with pio run -t upload; monitor at 115200. ESP-IDF requires a project path without spaces; copy this directory to a space-free path if needed. The existing scanner is separate and unchanged.

The default feather-esp32-s3 environment retains the 100 Hz / 104 Hz configuration. The stream-200 environment selects a 5 ms target and nominal 208 Hz for both sensors. It adds timing rows: timing,sweep,start_us,end_us,deadline_us. End is captured after the five sample rows are printed and before the timing row itself; a later start or timing-row output can also contribute to missed deadlines.

The profile-200 environment instruments each sweep and emits profile,sweep,start_us,end_us,deadline_us,mux_us,read_us,format_us,output_us. Times sum over five sensors. Formatting uses snprintf and output uses fwrite to separate their costs, so this profiling build changes the output path and adds measurement and profile-row overhead. The measured output time is time spent in the write call, not confirmed physical USB delivery time.

## Binary 200 Hz experiment

Select binary-200 to stream fixed 136-byte packets at a 5 ms target, with both sensors at nominal 208 Hz. Capture and summarize with python3 decode_binary.py capture.bin --port /dev/cu.usbmodem1101 --seconds 35 (requires pyserial); omit --port to analyze an existing capture.

All integers are little-endian. Header: bytes 0–3 ASCII FFIM; byte 4 version 1; byte 5 sensor count 5; bytes 6–7 packet length 136; bytes 8–11 uint32 sweep sequence; bytes 12–19 uint64 sweep-start timestamp; bytes 20–27 uint64 scheduled deadline; bytes 28–35 uint64 acquisition-end timestamp; bytes 36–43 uint64 previous packet write-completion timestamp (zero for the first packet). Timestamps are ESP timer microseconds since boot. Five 18-byte records follow at byte 44, one each for logical IDs 0–4 mapped to mux channels 3–7: uint8 ID, uint8 status register, uint8 error (0 success, 1 mux selection, 2 sensor read), uint8 reserved, uint16 microsecond offset from sweep start to completion of sensor read (saturates at 65535), then six signed int16 values in accelerometer XYZ, gyroscope XYZ order. Bytes 134–135 are CRC-16/CCITT-FALSE (polynomial 0x1021, initial 0xffff, no reflection or final XOR) over bytes 0–133. On an I²C error, the corresponding raw values are zero and the error byte must be checked. Scale raw acceleration by 0.000061 g/LSB and raw gyro by 0.00875 degrees/s/LSB; these are nominal sensitivities without bias calibration. Status bits 0/1 are accel/gyro ready at the start of the burst; they cannot count overwritten samples.

The deadline is the scheduled completion time of the current sweep. Acquisition-end excludes CRC and USB output; the next packet reports the previous write-completion time, allowing comparison against the previous deadline without counting scheduler wake-up jitter. Boot messages may precede the binary stream. A host not reading USB can cause backpressure; no separate diagnostic text is emitted in the timed stream.
