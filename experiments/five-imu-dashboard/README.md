# Five-IMU dashboard

Local-only USB serial bridge and browser viewer for the existing binary-200 firmware. Uses the packet decoder from ../embedded/five-imu-stream/decode_binary.py; pyserial is required. Start with python3 server.py and open http://127.0.0.1:8766. The bridge discovers this Feather by USB VID/PID 303A:1001 and serial number D0:CF:13:0A:F4:E0, and retries every second when it is missing. Use --serial-number for a different Feather; --port optionally prefers a specific path but still checks the USB identity. Pass --http-port to change the HTTP port. The server connects automatically; use Connect / Disconnect to restart or stop serial access. Stop the server with Ctrl-C.

The bridge reads every packet and batches samples for the browser; plots retain five seconds and draw at up to 20 frames/s. Values are nominally scaled, without sensor calibration or fusion. Incoming rate is measured at the bridge from packet arrivals; sequence gaps, CRC candidates and sensor error counts reset when the user starts a new connection; automatic reconnections retain the counters. A serial error or data older than 1.5 seconds is shown as disconnected/stale. A slow browser may drop batches without affecting the bridge's serial diagnostics. Only localhost can connect; do not expose this server to a network.

The Individual view stacks Thumb through Pinky, with acceleration and gyro charts together for each sensor. The Combined view groups five separate XYZ accelerometer graphs followed by five separate XYZ gyroscope graphs. Both views use the same data and preserve the single-IMU BMI323 dashboard's 2/5/10/30-second window, pause/resume, labeled grid, moving time axis, fixed ±2 g accelerometer scale, and automatic gyro scale. The original graph code and styling are in ../bmi323-gravity/app.js and style.css; the drawing routines are adapted locally so the original experiment stays unchanged.

Rendering runs on requestAnimationFrame independently of packet arrivals and draws only graphs intersecting the viewport. The device timestamp anchors a continuously advancing browser clock; missing samples are not interpolated. In the browser console, `window.imuRenderStats.snapshot()` reports observed FPS, frames over 25 ms, maximum and recent 95th-percentile frame interval, and mean/maximum render callback time. These measurements include the browser's scheduling and may be affected by background-tab throttling.

The Gravity view ports the earlier BMI323 GravityEstimator with one independent state per sensor. It rotates the body-frame gravity estimate using gyroscope readings and measured timestamp intervals, corrects toward normalized acceleration with a one-second time constant when magnitude is 0.5–1.5 g, and normalizes the result. Initial readings and gaps over 250 ms reinitialize from valid acceleration; serial reconnects reset the states. Linear acceleration can still influence the estimate, particularly when its magnitude remains in the accepted range, and gyro bias can cause drift. This is a unit gravity direction in sensor coordinates, not a separation of sustained linear acceleration from gravity.

The Gravity Gate view plots the positive estimated gravity Z component clamped to 0–1: 1 with the nail upward and 0 when horizontal or downward, assuming each sensor's Z axis follows the fingernail normal. It adds no smoothing or calibration and inherits the gravity estimator's limitations.

Physical mapping in anatomical order: Thumb channel 6, Index channel 7, Middle channel 5, Ring channel 4, Pinky channel 3. The browser applies this mapping to binary sensor IDs before updating each finger's history and gravity estimator; the firmware and bridge continue in channel order.

Gravity Gate displays all five mapped fingers on one 0–1 graph with a shared time axis and per-finger legend values. Each trace uses its own sensor timestamps and the same one-sided gate calculation.
